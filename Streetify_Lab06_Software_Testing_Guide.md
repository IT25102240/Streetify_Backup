## 🎯 Test Approach & Methodology

Each student member designed **10 test cases** for their assigned core module following the SLIIT standard template:
$$\text{Test Case ID} \;\vert\; \text{Test Title} \;\vert\; \text{Description} \;\vert\; \text{Preconditions} \;\vert\; \text{Test Steps} \;\vert\; \text{Test Data} \;\vert\; \text{Expected Output} \;\vert\; \text{Actual Output} \;\vert\; \text{Status}$$

Every individual suite strictly incorporates:
1. **Positive Tests:** Normal, valid feature execution asserting data persistence in MSSQL and clean UI transitions.
2. **Negative Tests:** Invalid, empty, or malformed inputs validating that Spring Boot Bean Validation (`@Valid`) and frontend regex catch errors and return HTTP 400 Bad Request / 401 Unauthorized / 409 Conflict.
3. **Boundary Value Tests:** Inputs at and just beyond limits (e.g., password lengths 7 vs 8 characters, star ratings 0 vs 1 and 5 vs 6, 5-minute passenger grace period timers, zero wallet balances, 200 audit log query limits).
4. **Role-Based Access Control (RBAC) & Security Tests:** Verifying Spring Security `@PreAuthorize` rules prevent unauthorized role switching, privilege escalation, or unauthenticated API tampering (HTTP 403 Forbidden).
